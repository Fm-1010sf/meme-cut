# meme-cut · 录屏变表情

把手机录屏里的一段动图，裁成微信能直接添加的 GIF。全程在浏览器本地跑，视频不出设备。

## 为什么是「录屏」

这条产品线的起点不是技术选择，是抖音把出口焊死了：

| 取文件的路 | 结果 |
| --- | --- |
| 私信表情长按保存 | 没有这个选项 |
| 评论区表情长按存入相册 | 实测不通 |
| 分享出去 | 只能在抖音内部转给别的抖音用户，不出应用 |
| 本地缓存翻文件 | Android 需 root，iOS 基本不可能 |
| 抓包 / 协议逆向 | 需越狱或证书植入，随版本失效，封号 |
| **录屏** | **唯一既合法又稳定的路** |

所以这个工具不碰任何抖音接口，只处理「你已经录下来的屏幕」。

## 用法

1. 抖音里录一段（控制在一两秒，越短越清楚）
2. 打开页面，选这段录屏
3. 拖时间轴截出表情出现的那一段
4. 拖裁剪框框住表情（默认锁正方形）
5. 选参数 → 生成 → 保存
6. 手机上长按这张 GIF → 存储到照片 → 微信从相册添加为表情

默认参数：200px 边长、12fps、1MB 上限。200px 是微信里表情的最大显示尺寸，给更大值是浪费体积。

## 微信侧的硬限制

这些数字**没有官方来源**：微信只对「表情商店上架」有公开规范，对「个人添加自定义表情」从来不写文档。下面是第三方实测，跨 2020–2024，版本可能已经变了。

| 约束 | 数值 | 来源 |
| --- | --- | --- |
| 表情最大显示尺寸 | 200×200（强制） | pic2meme README 2024-11，单一来源 |
| 添加为自定义表情 | ≥5MB 提示过大 | 百度百科，较旧 |
| 聊天里自动播放 | ≤1MB 自动播，以上需手动点 | 腾讯云社区自测 2020 |
| 自定义表情数量上限 | 999 | 微信 8.0.3 / 2021 |

**待办：拿这版工具实测一遍当前微信版本，把上表换成 2026 年的真实数字。**

## 压缩阶梯

体积优先降颜色，再降尺寸，最后才降帧率——因为这三者对观感的伤害是递增的：

```
最高画质 256色 → 高 192色 → 中 128色 → 中·缩半 192色@50% → 中低 128色@50%
→ 低 128色@50%+隔帧 → 小 96色@50%+隔帧 → 更小 96色@35%+隔帧
→ 最小 64色@35%+隔3 → 兜底 32色@35%+隔3
```

任一级塞进目标体积就停。全部走完仍超限，界面如实报错，不假装成功。

实测：纯色画面 200px/12fps/1MB → 170KB；随机噪声 240px/20fps/500KB → 自动缩到 120px、335KB，并提示已降级。

## 时间轴不能歪

GIF 的帧间隔只能是整数厘秒，而 12fps 是 83.3ms，除不尽。如果用「每帧 8 厘秒」硬套，
30 帧会播成 2.40 秒而不是 2.50 秒，累积出 4% 的快放。

所以编码时把余数攒着：`8, 8, 9, 8, 8, 9...` 交替，总时长就能对齐。测试里有一条断言专门盯这个。

**踩过的坑**：`gifenc` 的 `writeFrame` 里 `delay` 单位是**毫秒**（它内部再 `/10` 转厘秒）。
当成厘秒传会变成 10ms/帧，播放快 8.3 倍——而且帧数、体积、尺寸全都正常，只有时间不对，很难靠肉眼发现。

## 已知限制

- **iOS Safari 无法批量存图**：多张下载每张都要独立用户手势，浏览器会拦。所以只能逐张长按保存，这条是平台限制，做 App 才能绕过。
- **视频解码吃内存**：长录屏在低端机会崩。目前限制单次最多 180 帧，片段建议 ≤ 2.5 秒。
- **只接受视频**：静态表情也得录屏，多一道手续。下一步应该加图片直入。
- **未在真机验证**：开发期用 Edge 无头浏览器跑的端到端测试，iOS 上 `seek` 精度和 `canvas` 取帧的差异还没实测。
- **一次一个**：没有批量队列。

## 开发

```bash
pnpm install
pnpm dev          # http://127.0.0.1:5183
pnpm exec tsc --noEmit
pnpm exec vite build

# 端到端测试（需要 dev server 在跑）
pwsh -File test-fixture/make-fixtures.ps1 -Ffmpeg "C:\path\to\ffmpeg.exe"
node test-fixture/verify.mjs
```

测试素材（mp4/mov）体积大且能重新生成，所以没进仓库，跑测试前先用 `make-fixtures.ps1` 造一次。

测试脚本用 Edge 跑，覆盖：首屏渲染、视频首帧真的解码、动图帧数（按 GIF 规范逐块解析，不靠搜字节）、
**播放总时长与原片一致（防快放）**、体积上限、压缩阶梯降级提示、坏文件必须有可见错误、移动端横向溢出。

## 结构

```
src/
  lib/video.ts     载入、精确 seek、抽帧
  lib/gif.ts       全局调色板编码 + 体积阶梯
  components/
    CropOverlay.tsx  裁剪框（原始像素坐标系）
    Timeline.tsx     起止点与播放头
    ui.tsx           按钮/分段/滑杆，全部带微交互
  App.tsx          三阶段编排
```

技术栈：React 19 + Vite 8 + Tailwind 4 + Motion + gifenc + Lucide。没有后端，没有上传，没有账号。
